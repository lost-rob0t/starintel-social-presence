At 07:20 UTC on November 11, StarIntel's production writes moved to a three-node CouchDB cluster. Actor output still travels through RabbitMQ and the server's ingest bridge. HAProxy now sits between that bridge and the database nodes.

The migration also broke document full-text search. That failure survived the basic health checks and remained unresolved in the latest indexing record.

* Moving the database

The old arrangement put maintenance and incoming writes in competition. One operational snapshot showed about 282 messages arriving each second against roughly 26 acknowledgments. Storage contention needed investigation alongside worker capacity.

The cluster uses eight shards and three replicas, with a distinct backing disk for each node. All three nodes share the same virtualization environment. HAProxy gives clients a stable entry point, with authenticated backend checks and access restricted to the intended clients. Deliberate node-failure testing and sustained post-cutover throughput measurements are still outstanding.

Getting the nodes to agree took several repairs. SSH was consuming a convergence loop's member-list input, causing later nodes to be skipped. The firewall peer rules needed an active backend. Resetting one node locally was insufficient when surviving peers could gossip phantom shard membership back into it.

Fresh-cluster reinitialization preceded migration. A stale-branch deployment regressed membership at 01:01 UTC; recovery at 01:09 resumed replication without another wipe. This happened before the 07:20 cutover, while migration was still running.

The cutover journal records advancing writes and cross-node reads. Later database snapshots reached roughly *6.3 million aggregate stored documents*. That total includes migrated material; it supplies neither a newly collected count nor a Reddit collection rate.

* Shipping the image, finding the missing indexer

Authentication at the new database front exposed a faulty readiness probe. Anonymous checks received a 401 even while authenticated writes continued. The [[https://git.starintel.actor/starintel-labs/starintel-server/commit/024459c99065902f6eca07c1224cc0816c7a0bd4][server repair]] supplies the configured credentials without relaxing database authentication. The later clean image was recorded healthy from 17:21 UTC, after the storage cutover.

The first date-versioned production release, =v2026.11.11=, pinned that later server revision. At 17:55 UTC, the rollout had four targets committed and six in flight. Persistent-profile mismatches and stale failed-unit gates complicated deployment: a healthy running system could still differ from the profile selected for its next boot.

Document search had a separate cause. The cutover omitted Clouseau, which builds the full-text indexes. The synthetic stack used for checks included it, so those checks missed the production omission. Adding Clouseau across the three database nodes started 24 shard-indexing tasks. The latest relevant record still showed early progress and document-search timeouts.

Meanwhile, the [[https://search.starintel.actor/][public search facade]] has a live YaCy web-search slice. Activation checks returned HTTP 200 for an anonymous query, with zero hits. Public mode applies per-IP limits, fails closed around proxy trust, and excludes private billing, crawl and document-management routes. YaCy availability does not establish recovery of the document-search path.

* When a running container stops collecting

The fleet also stalled independently of the database move. An AMQP reset led into blocking consumer shutdown; an actor timeout could leave the process hanging. Containers stayed up, but heartbeats went stale and traffic stopped. The restart policy saw a living main process.

After a fleet restart, one observation recorded 18 healthy containers and about 134 events per second. A host-local check now restarts unhealthy actor containers every two minutes. It covers actors only; the server consumer needs separate handling for a similar wedge.

An invalid username-target stream was stopped and more than half a million queued items removed. Those were unusable documents, excluded from useful-ingestion totals. Completed quarantine replay is still unconfirmed.

* More specific collection jobs

The following implementations have merged; production scheduling is a separate deployment step.

The GitHub collector accepts bounded user, organization and repository jobs. It collects commits and activity with explicit fork and authorship relations, retaining public commit-email provenance and distinguishing noreply markers. The bounds keep a repository request from expanding indefinitely through connected accounts.

Site-watch persists page snapshots and compares status, title and link structure to produce deltas and alerts. Restarting the actor preserves the comparison history. Wayback CDX and certificate-transparency polling provide additional sources; browser rendering is a target option. An unchanged-page regression fixture checks against alerts caused merely by another visit.

The search actor normalizes provider results into URL records and can submit URLs to YaCy. Deterministic query and URL job identifiers help recognize repeated work. Its HTTP acceptance receipt confirms submission, not completed crawling or indexing.

The scraper designer fetches and sanitizes an HTTPS sample, then requests a definition using a pinned vocabulary. Proposed manifests must stay on the sampled origin. Execution uses a restricted Docker network and an allowlisted provider proxy; reserved actor identifiers are rejected. Injection-marker scanning adds a limited check. The output remains a proposed definition requiring validation.

Anonymous X support is narrower: HTTP handle probing and logged-out rendered profiles. Automatic backend selection chooses the probe when no session accounts are configured. Neither anonymous backend collects posts, threads or search results, and this selection is not dynamic failover.

* Learning code and a repaired research site

The November 8 learning changes merged on GitHub but have not reached canonical Forgejo main. They implement bounded symbolic concept discovery and [[https://github.com/starintel-labs/star-kb/commit/68e18bcd0aacf75fc71443ce487701fc48b5db1c][passage discovery with evidence planning]].

The metadata path proposes operational definitions from repeated scalar equivalences. Evaluation requires separately recorded annotations and held-out positive and negative pairs with source separation. It retains confusion counts and finite-sample uncertainty.

Passage discovery defaults to exact repeated six-word windows, preserving source spans and normalized digests. Text and cached-window limits bound the work. A quotation or shared upstream source can explain the same match, so the next step is to collect evidence that distinguishes those explanations.

The resulting plan records the evidence needed to distinguish competing explanations, alongside missing collector inputs. Selecting a collector in the plan does not grant access or start a run.

The research site had its own delivery failure: it was stuck on an October 30 branch snapshot. Corrected source discovery now feeds an immutable Nix build, activated through an atomic current-link switch and a persistent refresh timer. Web activation was recorded after the repair.

The [[https://git.starintel.actor/starintel-labs/starintel-auto-research/commit/5754e6fe1b48b86b4f6f6564061325d89e609086][backlog cleanup]] archived 97 stale, unapproved documents and repaired links around the moves, reducing the pending set from 105 to eight. The old proposals remain available in the archive. Changed-document validation cleared; legacy full-corpus issues remain.

* Accounts and operator tools

Account integration remains on unmerged branches. The backend implements an OIDC relying party with a server-side, single-use PKCE verifier, account and key responses, and logout. Dashboard work adds console views and reveal-once keys. The Quasar branch selects password or OIDC mode at runtime and handles the return destination and authentication errors. Identity-authority infrastructure merged, but deployment still had a discovery failure after an address mismatch. A deployed sign-in and logout round trip remains undemonstrated.

A previously unreported November 4 addition gave the infrastructure expert queryable diagnostic tables and an adapter for recorded incident remedies. The tables identify response choices and authorization requirements; they do not run repairs. Pi's separate feature branch adds shared Prolog state and background-completion events. Its completion gate is advisory: requirements can be removed, and a continuation limit eventually permits settlement with failures. Merge and live acceptance are pending.

The next production work is to finish indexing and verify document-search results, converge the six in-flight release targets and their boot profiles, and test a node interruption under writes. Quarantine replay and backend-specific unique-post measurements still need runs; account integration still needs its deployed round trip.
