* Stage 2 — configure local secrets

The server README/DOCKER quick-start historically listed the database/broker
secrets.  The current authenticated stack additionally consumes the auth pepper
and one-time bootstrap secret, as exercised by =scripts/stack-test.sh=.  The
video uses the current stack-test-derived set.

#+begin_src sh
cp .env.example .env
install -d -m 0700 secrets

openssl rand -base64 32 > secrets/couchdb_password
openssl rand -base64 48 > secrets/couchdb_secret
openssl rand -hex 24 |
  tr '[:lower:]' '[:upper:]' > secrets/erlang_cookie
openssl rand -base64 32 > secrets/rabbitmq_password
openssl rand -base64 32 > secrets/valkey_password
openssl rand -base64 48 > secrets/auth_pepper
openssl rand -base64 48 > secrets/auth_bootstrap_secret

chmod 0600 secrets/*
#+end_src

Do not run =cat secrets/*= while recording.

Validate the Compose model:

#+begin_src sh
docker compose config --quiet
#+end_src

If Compose requires an actor-profile secret even though the =actors= profile is
disabled, create a random local placeholder and rerun config:

#+begin_src sh

chmod 0600 secrets/youtube_actor_api_key
docker compose config --quiet
#+end_src

* Stage 4 — bootstrap a local API key without displaying it

#+begin_src sh
bootstrap_secret="$(<secrets/auth_bootstrap_secret)"

curl --fail --silent --show-error   --request POST   --header 'Content-Type: application/json'   --header "X-Star-Bootstrap-Secret: $bootstrap_secret"   --data '{"owner":"youtube-demo"}'   --output "$STARINTEL_DEMO_ROOT/bootstrap.json"   http://127.0.0.1:5000/auth/bootstrap

api_key="$(
  jq --exit-status --raw-output '.api_key'     "$STARINTEL_DEMO_ROOT/bootstrap.json"
)"

test -n "$api_key"
printf 'local StarIntel credential created\n'
#+end_src

Never display =bootstrap.json= or =$api_key=.

Show only authenticated context:

#+begin_src sh
curl --fail --silent --show-error   --header "Authorization: Bearer $api_key"   http://127.0.0.1:5000/auth/context |
  jq '{principal_id, principal_type, owner}'
#+end_src

Acceptance:

- [ ] Bootstrap succeeds exactly once on the fresh auth DB.
- [ ] API key parses with =jq=.
- [ ] Authenticated context exits zero.
- [ ] Published frame contains no bearer token.

* Fallback steps

** Server build is slow

Prewarm Nix/Docker before the take.  During recording show:

1. the exact command starting;
2. a jump cut;
3. the same terminal after successful completion;
4. =docker compose ps= and =/health= as proof.

Do not fabricate elapsed-time claims.

** Server stack fails

Run:

#+begin_src sh
docker compose ps --all
docker compose logs --no-color star-server | tail -n 200
docker compose logs --no-color couchdb | tail -n 120
docker compose logs --no-color rabbitmq | tail -n 120
#+end_src

Fix/rehearse before recording.  Do not record around a broken stack.

** Quasar actor fails

Required actor fallback is not a different claim.  Use the public test suite as
a diagnostic:

#+begin_src sh
cd "$STARINTEL_DEMO_ROOT/quasar-ui"
npm run check
npm test
#+end_src

If the exact target actor path is broken on current main, update the video
source to the newly verified public path or postpone the actor shot.

** Legistar fails

Skip it.  It is optional.

** Auto Dig validation fails

Do not show the corpus as validated.  Capture the failure only if the video is
explicitly discussing a current bug; otherwise rehearse on a passing revision.
