StarIntel turns collected material into typed documents with traceable sources.
Start with a small synthetic workspace, learn the tools, then connect a server
or add collectors when you need them. You do not need to deploy the whole stack
to learn the document workflow.

* Recommended learning path

1. [[file:tutorials/getting-started.org][Create a local operation and a synthetic note]]. Nothing is collected or published.
2. [[file:tutorials/cli.org][Read, revise, search and export it]] from the terminal.
3. [[file:tutorials/mcp.org][Connect the same workspace to an assistant]]. The CLI and MCP see the same data.
4. [[file:tutorials/api-keys.org][Authenticate to a server]], inspect your capabilities and publish only when authorized.
5. [[file:tutorials/actors.org][Add one actor]] after the server and broker are healthy.

* Which project do I need?

[[file:projects.org][The project guide]] explains each component's purpose, first action,
configuration boundary and next tutorial. In short:

- =starintel-mcp=: local operations engine, MCP stdio server, CLI and local web UI.
- =starintel-client=: maintained Python HTTP client, driven by the server's registry.
- StarIntel Server: durable backend, authorization, ingest, search and scheduling.
- Pro actors: optional collection/enrichment workers, not an alternate server.
- StarLang and =starintel-doc=: generated document contract and language consumers.
- Quasar: connected control/runtime and presentation; not a replacement for storage.
- Auto Dig and Auto Research: separate corpus and research workflows.

* Starter checkout

=starintel-intro= contains pinned source references, setup, an offline demo,
MCP configuration generators, key handling examples and a local-server preparation
helper. In the documentation source checkout it lives at =starter/starintel-intro/=.
See [[file:tutorials/getting-started.org][the first tutorial]] for obtaining it. Source access and server
access are separate permissions; no API key or private dataset is bundled.
